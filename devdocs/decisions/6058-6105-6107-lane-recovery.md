# ADR: lane recovery resumes what failed instead of relaunching or parking blind

## Context

2026-11-26 failure-class census (`devdocs/evidence/2026-11-26-pipeline-failure-classes.md`) showed three lane-recovery gaps:

- #6058: a deliver requirement with no status row in `result.json` (the builder skipped it) got the generic conformance resume, then parked `conformance.unimplemented` twice in a row.
- #6105: a builder session ending `is_error: true`, `terminal_reason: "api_error"` after 50 turns ended the lane `engine-error` and the batch relaunched it from scratch (about $1.15 lost).
- #6107: a `verify.precheck_block` / `ci.red` park kept the check command but not the failing check's name or output, and a `ci.red` recovery ran the checks on a branch that was behind (or conflicting with) its base.

## Choice

- No status row: `conformance.mjs` marks the failure `kind: "requirement_no_status"` with `reqId` and `quote` (code stays `conformance.unimplemented`). `conformanceResumePrompt` then opens with a targeted ask naming each skipped id and its quote. If the row is still missing, the park detail starts `The builder did not address R#` and the lane result carries `kind: "requirement_no_status"` and `requirements`. The failure census still buckets it as `no_status`.
- API termination: `runner.mjs` keeps `terminal_reason` and `session_id` from the CLI envelope (`cliTerminalReason`, `cliSessionId`) and sets `err.apiError` for a transient API reason (not a login failure, usage limit or never-reached-the-API exit). `builder()` resumes that session (`--resume <id>`) after 20 s, 60 s, 180 s; the worktree and commits are kept. After three failed resumes, or with no session id, the lane defers `backend.cli_failed` (capped short retry, never the breaker, never engine-error). The run log records `API_ERROR_RESUME` and `RUN_TERMINAL.api_resumes`, so resumes are counted apart from relaunches.
- Check output: `checkFailureTail` (`bin/lean/precheck.mjs`) renders the failing check's name (CI job name, else the command) and the last 40 lines of its output with secrets redacted (`redactSecrets`). All precheck parks (including refactor:split) use it, and a `PRECHECK_FAILED` run-log event carries the same text.
- Stale base: a `ci.red` recovery lane merges the fetched base before running any check when the branch is behind. A conflict the deterministic resolvers (`baseMerge` config) cannot resolve ends `base.conflict` (recoverable) with the merge aborted; the checks never run on that tree.

## Consequences

- A skipped requirement costs one targeted resume and parks with a different message than a failing check, so triage no longer needs to open the result file.
- A transient API error costs at most three resumes of the same session instead of a whole lane.
- The base-sync is limited to `ci.red` recovery lanes; a first lane's base sync still happens at PR time.
